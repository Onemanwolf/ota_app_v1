Ops Triage Agents

The app receives Dynatrace problems for a Kafka platform, decides what to do about each one, and acts through tools it does not own. A second job reviews Kafka logs and metrics daily and reports trends, risks and likely root causes. Everything a model says is checked by code before it reaches anyone.

Context map

Each bounded context is its own service with its own PostgreSQL schema. Dynatrace formats enter only through anti-corruption layers (ACL) that map them to one published event, ProblemEvent. Triage never touches Teams, tickets or Docker directly: it asks the owning context through MCP tools.

Triage flow, end to end

A problem is accepted in milliseconds and triaged asynchronously. The inbox is transactional, so a webhook is never lost and a crashed worker's alert is picked up again when its lease expires.

Decision node. classify calls the configured decision model. If the model fails or returns something invalid, a safe rules decision is used and the error is recorded on the run.

Branching nodes. notify, ticket, escalate and remediate are action agents. The policy gate, not the model, decides which of them run.

Remediation subgraph

A restart is the only action that changes infrastructure, so it passes several checks. The target always comes from the registry, never from model output or log text. Manual approval pauses the graph with interrupt(); the state is checkpointed in Postgres and the alert waits in awaiting_approval until a person decides.

Rules and signatures: the "rule or signature decided" path

In the graph, pre_route runs two kinds of fixed, code-only checks before any model is asked. The first match wins: the action is decided there, recorded with source: rules, the check's id and the facts that fired it, and the run goes straight to the policy gate. In the Kafka test set, this path decided 131 of 150 cases; only 19 reached the model.

Policy rules are about the problem's circumstances: maintenance, a test notification, a merged duplicate. They live in config, so operations can change them without a release.

Kafka signatures are about Kafka behaviour: metric values against documented Kafka thresholds and specific Kafka log messages. They live in code, with tests, because they encode Kafka knowledge.

A restart decided by a signature still passes the target checks and human approval in the remediation subgraph.

Policy gate

The gate turns a decision into a plan. A decision can only lower autonomy, never raise it. Every plan starts with notify, except suppress, which is audit only.

Health review

The review is advisory: it never restarts or changes anything. Code collects, redacts and summarises the data into a digest with citation ids. The model only reasons over that digest, and the validator rejects any finding that does not cite real evidence. Threshold breaches become findings whatever the model says.

Root-cause analysis

For one Dynatrace problem, the same pipeline runs on a window from 2 hours before the problem started until it ended. Code builds a timeline of what changed first: each metric's first sustained departure from the 3 hours before the window, and log templates that first appear inside it. The analyst ranks causes from that timeline; a signal that changed earlier is more likely a cause, one that changed later more likely an effect.

Retention

Raw data is kept briefly; trend history is re-read from Dynatrace at review time and never copied. A purge job runs every 15 minutes: it deletes expired evidence and reports, and turns an expired review into a tombstone (id, cluster, kind and times only) for 30 days, so its link answers 410 Gone instead of 404. The purge log records counts, never content.

Glossary

ProblemEventThe one event shape every Dynatrace delivery path is mapped to (the published language).
Anti-corruption layerAn adapter that translates an outside format into the app's own model at the boundary.
Kafka signatureA deterministic rule over metrics and log identifiers, such as offline partitions above 0, that decides an action without a model.
Policy gateTurns a decision into a plan of actions using thresholds, target autonomy and severity.
DigestThe redacted, code-computed summary the review model reads, with an id for every piece of evidence.
BreachA metric outside a documented Kafka normal value for longer than its minimum duration.
System OneThe decision API shared by Kev, Jev and Microsoft-Decision-1: a state plus typed questions.
